# FLUIDE Atelier

Первый каркас интернет-магазина парфюмерного бренда FLUIDE.

Сайт создан на HTML, CSS и JavaScript без фреймворков. В проект перенесены
фирменные логотипы, шрифты, палитра и часть каталога для демонстрации.

## Структура

- статический интерфейс находится в корне проекта;
- API на Node.js находится в `server/`;
- миграции PostgreSQL находятся в `server/migrations/`;
- секреты хранятся только в `.env` локально или `/etc/fluide/fluide.env` на сервере.

## Локальный запуск

```bash
npm install
cp .env.example .env
npm run migrate
npm start
```

## Публикация

Продакшен-сайт обслуживает Nginx. API работает отдельным systemd-сервисом только
на `127.0.0.1:3000`, а PostgreSQL принимает соединения только с localhost.

## FLUIDE CMS

Панель управления открывается по адресу `/admin/`. У неё отдельные сотрудники, роли и
защищённые сессии; кабинеты покупателей не дают доступа в CMS. Первый сотрудник создаётся
серверной командой, которая генерирует начальный пароль и не требует вводить его в shell:

```bash
npm run admin:create -- --email=owner@example.com --name="Владелец" --role=owner
```

Текущий JSON-каталог переносится в PostgreSQL автоматически и идемпотентно:

```bash
npm run catalog:import
```

Импорт создаёт 99 ароматов и 37 остальных товаров. Все позиции используют режим
`made_to_order` со сроком подготовки один день. Себестоимость, складской остаток и резерв
в модель не входят. В CMS можно менять карточки, варианты, цены, изображения и SEO-поля,
а также безопасно предварительно проверить и применить импорт XLSX.

Таблица `integration_links` заранее отделяет внутренние товары и варианты от внешних ID.
Она предназначена для будущего обмена с «МойСклад» без перестройки каталога; токены и сам
обмен пока не подключены.

## Яндекс ID

Для входа через Яндекс в защищённом файле окружения должны быть заданы:

```dotenv
YANDEX_CLIENT_ID=...
YANDEX_CLIENT_SECRET=...
YANDEX_REDIRECT_URI=https://fluide-atelier.ru/api/auth/yandex/callback
```

Секрет нельзя добавлять в Git. OAuth-поток использует `state` и PKCE, а токены Яндекса не
хранятся в браузере или PostgreSQL.

## VK ID

Для отдельного кабинета VK ID задайте публичный идентификатор приложения и точный callback:

```dotenv
VK_CLIENT_ID=54774890
VK_REDIRECT_URI=https://fluide-atelier.ru/api/auth/vk/callback
```

VK ID использует OAuth 2.1 с `state` и PKCE. Сайт запрашивает только необязательный email;
номер телефона, дата рождения и пол не запрашиваются. Токены VK не сохраняются.

## Вход по телефону

Яндекс ID, VK ID и телефон являются независимыми способами регистрации и могут вести в
разные личные кабинеты. Сайт не объединяет их автоматически. Телефонный кабинет создаётся
только после успешной проверки одноразового SMS-кода; повторный вход с тем же номером
открывает тот же телефонный кабинет.

Локально код выводится только в серверную консоль при `SMS_PROVIDER=console`. В production
этот режим запрещён. Для SMS.RU задайте в `/etc/fluide/fluide.env`:

```dotenv
SMS_PROVIDER=smsru
SMS_RU_API_KEY=...
# Необязательно: заранее согласованное имя отправителя
SMS_SENDER=
```

Ключ SMS-провайдера нельзя добавлять в Git или передавать браузеру. API ограничивает частоту
отправки по IP и номеру, общий дневной расход SMS, срок жизни кода и число попыток проверки. Пользователь
не создаётся до успешной проверки кода. Формат запроса соответствует
[официальной документации SMS.RU](https://sms.ru/docs/api/api_group_sms/send).
