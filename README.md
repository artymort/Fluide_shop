# FLUIDE Atelier

Первый каркас интернет-магазина парфюмерного бренда FLUIDE.

Сайт создан на HTML, CSS и JavaScript без фреймворков. В проект перенесены
фирменные логотипы, шрифты, палитра и часть каталога для демонстрации.

## Структура

- статический интерфейс находится в корне проекта;
- API на Node.js находится в `server/`;
- миграции PostgreSQL находятся в `server/migrations/`;
- секреты хранятся только в `.env` локально или `/etc/fluide/fluide.env` на сервере.

## Локальный запуск

```bash
npm install
cp .env.example .env
npm run migrate
npm start
```

## Публикация

Продакшен-сайт обслуживает Nginx. API работает отдельным systemd-сервисом только
на `127.0.0.1:3000`, а PostgreSQL принимает соединения только с localhost.

## FLUIDE CMS

Панель управления открывается по адресу `/admin/`. У неё отдельные сотрудники, роли и
защищённые сессии; кабинеты покупателей не дают доступа в CMS. Первый сотрудник создаётся
серверной командой, которая генерирует начальный пароль и не требует вводить его в shell:

```bash
npm run admin:create -- --email=owner@example.com --name="Владелец" --role=owner
```

Текущий JSON-каталог переносится в PostgreSQL автоматически и идемпотентно:

```bash
npm run catalog:import
```

Импорт создаёт 99 ароматов и 37 остальных товаров. Все позиции используют режим
`made_to_order` со сроком подготовки один день. Себестоимость, складской остаток и резерв
в модель не входят. В CMS можно менять карточки, варианты, цены, изображения и SEO-поля,
а также безопасно предварительно проверить и применить импорт XLSX. Раздел «Страницы»
управляет главной страницей: баннером, промоблоками, текстами, изображениями и упорядоченным
списком бестселлеров. Контент сначала сохраняется как черновик, затем публикуется отдельно.

Таблица `integration_links` заранее отделяет внутренние товары и варианты от внешних ID.
Она предназначена для будущего обмена с «МойСклад» без перестройки каталога; токены и сам
обмен пока не подключены.

Удаление заказа в CMS переносит его в архив, откуда владелец или администратор может восстановить
заказ. Тестовые и неоплаченные заказы автоматически удаляются окончательно через 14 дней после
архивации. Заказы с подтверждённой настоящей оплатой остаются в архиве без ограничения срока,
чтобы не потерять связанную платёжную историю.

Заказы, для которых покупатель открыл ЮKassa, но не завершил платёж, показываются в CMS отдельно.
Через 30 минут они помечаются как незавершённая оплата, через 24 часа автоматически переносятся
в архив, а ещё через 14 дней удаляются. Если успешное уведомление ЮKassa придёт позже, заказ
автоматически восстанавливается и возвращается в рабочий список. Пока платёж не завершён, сайт
предлагает покупателю продолжить оплату или отменить заказ и не создаёт поверх него дубликат.

## Яндекс ID

Для входа через Яндекс в защищённом файле окружения должны быть заданы:

```dotenv
YANDEX_CLIENT_ID=...
YANDEX_CLIENT_SECRET=...
YANDEX_REDIRECT_URI=https://fluide-atelier.ru/api/auth/yandex/callback
```

Секрет нельзя добавлять в Git. OAuth-поток использует `state` и PKCE, а токены Яндекса не
хранятся в браузере или PostgreSQL.

## VK ID

Для отдельного кабинета VK ID задайте публичный идентификатор приложения и точный callback:

```dotenv
VK_CLIENT_ID=54774890
VK_REDIRECT_URI=https://fluide-atelier.ru/api/auth/vk/callback
```

VK ID использует OAuth 2.1 с `state` и PKCE. Сайт запрашивает только необязательный email;
номер телефона, дата рождения и пол не запрашиваются. Токены VK не сохраняются.

## Вход по телефону

Яндекс ID, VK ID и телефон являются независимыми способами регистрации и могут вести в
разные личные кабинеты. Сайт не объединяет их автоматически. Телефонный кабинет создаётся
только после успешной проверки одноразового SMS-кода; повторный вход с тем же номером
открывает тот же телефонный кабинет.

Локально код выводится только в серверную консоль при `SMS_PROVIDER=console`. В production
этот режим запрещён. Для SMS.RU задайте в `/etc/fluide/fluide.env`:

```dotenv
SMS_PROVIDER=smsru
SMS_RU_API_KEY=...
# Необязательно: заранее согласованное имя отправителя
SMS_SENDER=
```

Ключ SMS-провайдера нельзя добавлять в Git или передавать браузеру. API ограничивает частоту
отправки по IP и номеру, общий дневной расход SMS, срок жизни кода и число попыток проверки. Пользователь
не создаётся до успешной проверки кода. Формат запроса соответствует
[официальной документации SMS.RU](https://sms.ru/docs/api/api_group_sms/send).

## ЮKassa

Для тестовой интеграции задайте параметры только в защищённом файле окружения:

```dotenv
YOOKASSA_SHOP_ID=...
YOOKASSA_SECRET_KEY=...
YOOKASSA_TEST_MODE=true
YOOKASSA_RETURN_URL=https://fluide-atelier.ru/checkout.html?payment=return
```

Секретный ключ нельзя добавлять в Git, клиентский JavaScript или журналы. При включённом
тестовом режиме сервер принимает только ключ с префиксом `test_` и дополнительно проверяет,
что созданный платёж действительно тестовый. Сумма и состав заказа всегда берутся из базы.

HTTP-уведомления тестового магазина направляются на:

```text
https://fluide-atelier.ru/api/payments/yookassa/webhook
```

Нужно включить события `payment.succeeded` и `payment.canceled`. Полученное уведомление не
считается доверенным само по себе: сервер повторно запрашивает платёж в API ЮKassa и сверяет
магазин, тестовый режим, заказ, сумму и валюту. Онлайн-оплата доступна для самовывоза и для СДЭК
после серверного расчёта и выбора ПВЗ. Для Почты России оплата пока остаётся на ручном этапе,
так как её доставка ещё не рассчитывается автоматически.

Перед включением настоящих платежей нужно заменить реквизиты на отдельный рабочий магазин,
установить `YOOKASSA_TEST_MODE=false` и настроить фискализацию/онлайн-кассу в соответствии с
системой налогообложения бизнеса.

## СДЭК

Для расчёта доставки и показа ПВЗ задайте в защищённом файле окружения:

```dotenv
CDEK_ACCOUNT=...
CDEK_SECURE_PASSWORD=...
CDEK_API_BASE=https://api.cdek.ru/v2
CDEK_CREATE_ORDERS=false
CDEK_FROM_CITY=Владимир
CDEK_PACKAGE_WEIGHT_GRAMS=1000
CDEK_PACKAGE_LENGTH_CM=25
CDEK_PACKAGE_WIDTH_CM=20
CDEK_PACKAGE_HEIGHT_CM=15
```

Текущий режим намеренно допускает только OAuth, поиск города/ПВЗ и расчёт тарифа. Метод
создания отправления в коде отсутствует, а `CDEK_CREATE_ORDERS=true` блокирует запуск. Это позволяет
безопасно использовать уже действующий ключ другого магазина для теста, не создавая в аккаунте СДЭК
ни накладных, ни заказов. Рассчитанная сумма подписывается сервером и повторно проверяется при
создании заказа, поэтому браузер не может подменить стоимость оплаты.

На оформлении заказа СДЭК доступен только до пункта выдачи. Пользователь выбирает город из подсказок,
после чего список ПВЗ загружается автоматически. Индекс и адрес получателя для этого сценария не нужны,
а стоимость фиксируется после выбора конкретного ПВЗ.
